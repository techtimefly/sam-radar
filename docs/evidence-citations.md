# Evidence And Citation Foundation

SAM Radar stores proposal evidence in SQLite so source facts can survive report regeneration, document re-parsing, and human review.

## Data Model

`evidence_citations` links a citation to:

- `notice_id`: opportunity identifier.
- `proposal_id`: optional proposal workspace.
- `document_id`: optional proposal document.
- `revision_id`: optional proposal/document revision identifier.
- `page_section`: page, heading, clause, or section label.
- `source_excerpt`: verbatim source excerpt used as evidence.
- `extracted_claim`: normalized claim inferred from the excerpt.
- `extraction_method`: `manual`, `document-intake`, `ai-assisted`, `imported`, or `legacy-snippet`.
- `confidence`: `0` through `1`.
- `verification_state`: `generated`, `needs-review`, `verified`, `rejected`, or `superseded`.
- `verifier`, `verified_at`, `created_at`, and `updated_at`.

The migration is additive and safe at app startup. Existing `evidence_snippets` remain in place for backwards compatibility. Document parsing writes both legacy snippets and citation records; existing consumers can keep reading `snippet`, `section`, and `reviewed` aliases from citation payloads.

## API

Reads are unauthenticated:

```text
GET /api/evidence/{noticeId}
GET /api/proposal-documents/{noticeId}
```

Writes require `APP_WRITE_TOKEN` in `X-SAM-RADAR-TOKEN`:

```text
POST /api/evidence/add
POST /api/evidence/update
POST /api/evidence/verify
POST /api/evidence/delete
```

All SQL uses parameter binding. Invalid confidence, verification state, extraction method, missing `noticeId`, or missing source excerpt returns a validation error. Evidence verification is server-side notice-scoped: `POST /api/evidence/verify` requires `{ noticeId, evidenceId, state, verifier }`, and the store rejects evidence IDs that do not belong to the supplied notice.

## Verification Workflow

The generated report shows citation cards in the opportunity/proposal document intake surface. Each card shows section, method, confidence, state, extracted claim, and a click-to-view source excerpt. Human reviewers can mark citations as verified, needs-review, rejected, or superseded after unlocking with `APP_WRITE_TOKEN`.

## AI Assist Boundary

Summary, Requirements, and Gap assist read citation records when present and fall back to legacy snippets. Outputs distinguish:

- Source facts: citation excerpts and SAM.gov description facts.
- Business assumptions: local fit rationale and capture context.
- AI recommendations: actions generated by deterministic or AI assist logic.

Prompts, source text, API keys, and excerpts are not stored in the AI audit log. When AI is disabled or unavailable, deterministic extraction produces stable output from report fields and citations.
